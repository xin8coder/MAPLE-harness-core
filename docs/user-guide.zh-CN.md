# MAPLE Harness 中文使用指南

[下载新版](https://github.com/xin8coder/MAPLE-harness-core/releases/latest) | [English](user-guide.md) | [返回首页](../README.zh-CN.md)

## 1. 安装并打开网页

Windows 下载 source ZIP，Linux 下载 source tar.gz，先**完整解压**。Windows 双击 `start.cmd`；Linux 在解压目录执行 `bash start.sh`。不需要提前安装 Python、Node、Docker 或 WSL，也不需要管理员权限。

首次启动会下载依赖，终端显示分阶段进度，可能需要几分钟。后续启动复用已安装内容。成功后自动打开浏览器，使用期间保留终端，按 Ctrl+C 停止服务。

如果没有自动打开浏览器，将终端显示的完整启动链接复制到本机浏览器。无桌面的远程服务器需要结合 SSH 转发或[内网部署](operations.md#intranet-and-background-deployment)。单独标注的桌面客户端只连接既有服务器，不能替代完整部署包。

## 2. 填写 API Key

打开 **Settings → MAPLE Harness**，填写 DeepSeek API Key，按需调整默认迭代次数，默认值是 **100**。应用各角色使用 `deepseek-flash`，不调用 Pro。真实模型请求消耗你的服务商额度，本地数值搜索与模型调用是两部分开销。

应用不要求注册账号或输入用户名/密码，浏览器通过启动链接与本机服务配对。该链接包含访问令牌，请不要发到公开群、截图或 issue。API Key 也不要填进问题文本或上传的数据表。

## 3. 提出需求并上传文件

选择工作区并新建对话，用自然语言说明想安排什么、希望改善什么、哪些条件不能违反。点击输入区的 **Document**，可以在提问时一起上传 Excel 或其他支持的文件，不需要提供服务器上的绝对路径。

支持 XLSX、CSV、TSV、JSON、JSONL、TXT、Markdown、PDF 和 DOCX；默认单个文件不超过 **25 MiB**。扫描图片可能需要先转成可读取文字。文档被截断时应先检查准备结果，不要直接当作完整输入继续求解。

中文提问会得到中文回复，不必额外要求“使用中文”。中文表头可以由 LLM 辅助映射为内部字段别名，并保留原始名称、数据值、标识和单位。业务规则不明确时，先让智能体确认，不要假设系统知道你没有提供的条件。

## 4. 用附带的中文 Excel 走一遍

进入[中文示例目录](../examples/garment_export/inputs/chinese/)，准备好 `服装外贸排产数据.xlsx`。在新对话中上传这个文件，并发送 `初始需求.txt` 的内容：

> 我们是一家服装外贸小公司，明天有六批货要打包出港，订单、班组和仓区都在附件里。
> 帮我排一下哪个班组做哪单、先做什么，再安排放哪个仓区。我想省点钱，也不想耽误客户截单，给我几种方案选。不能拆单、超仓区容量，也别让工人无限加班，具体规则按表里写的来。
> 先看看数据，帮我确认一下怎么安排、可以怎么求解，先不要开始算。

确认输入、规则和求解方式后，发送 `确认求解.txt`：

> 用遗传算法先小规模试排吧，六十个候选，最多四十代。费用和逾期分开看，不要合成一个分数。工资是每个人的时薪，准备时间也要付整组的工资。其他按表里的规则，开始吧。

这里的 **60 个候选、40 代**仅是这个示例的设置，不是全局默认值。示例使用模拟业务数据，不是客户的真实生产计划。用于实际排产前，应检查输入、计算方式和方案是否满足业务条件。

## 5. 选择求解方式

可表达为支持的线性/整数模型时，可以选择精确求解；复杂问题或多目标方案比较可以选择遗传算法。也可以要求智能体自动判断，并在开始前确认方式和预算。

“费用和逾期分开看”表示保留两个目标，供你比较折中方案，不会默认合成一个权重分数。遗传算法给出搜索得到的候选方案，有限迭代次数不等于保证找到全局最优。成本口径、单位、硬约束及模糊优先级都应先确认清楚。

## 6. 查看进度与选择方案

求解中，进度组件会显示当前阶段、迭代次数、可行解和解集规模，智能体会保持静默。一次任务包含数据准备、模型生成和数值搜索，不是提交后立即开始每一代计算。

完成后进入同一对话的 **Solutions（方案）**，查看各目标的迭代曲线、最终种群、帕累托解和导出文件。点击 **Explore and select a plan** 打开独立窗口，高亮一个可行方案，查看目标值和具体决策，再保存选择。

这里保存的是你的方案偏好，不会因为点选就执行实际生产，也不会自动把优化器的已接受状态改写成该方案。左侧切换对话时，方案页会跟随切换，不需要另选一次产物会话。

## 7. 在同一任务上追加更新

发送 `更新需求.txt`，不要另开一个无关的新任务：

> 客户刚通知，英国那批衬衫的截单改到中午十二点半，比原来提前两个小时。另外乙组有一个人请假，只剩三个人，其余条件和报价不变。
> 在刚才的任务上重新排一下，还是同时看费用和逾期，计算规模也不变。新旧方案都保留下来，方便我比较。

系统基于之前已接受的任务应用修改，检查旧候选是否适合复用。构造重启种群后，进度区会显示重启方式和复用数量。你可以在 **Solutions** 中分别检查初始任务和更新后的需求、目标值与结果。

如果这次更新失败，上一份已接受状态仍会保留。应先看错误提示或澄清需求，再重试，不需要清空历史来“修好”问题。

## 8. 下载结果、关闭与再次打开

使用结果视图中的下载入口获取 CSV、JSON 或 ZIP。产物可包含解集、最终种群、迭代记录及字段映射。请用结果下载链接，不要把宿主的 **Open Path** 当成浏览器下载。

按 Ctrl+C 停止后，任务仍保存在应用目录：Linux 为 `~/.local/share/maple-harness`，Windows 为 `%LOCALAPPDATA%\MAPLEHarness`。重新运行启动器可以继续查看。升级前先备份该目录、停止旧服务，再解压新版启动。不要删除数据目录来排查安装问题，也不要让两个后端同时写同一份状态。

## 常见问题

| 情况 | 建议 |
|---|---|
| 第一次启动一直在安装 | 看终端的分阶段输出；依赖下载需要网络，后续不必重复完整下载。 |
| Windows 找不到脚本 | 完整解压 ZIP，不要只提取或直接在压缩包内运行 `start.cmd`。 |
| 浏览器没打开 | 使用终端里的完整启动链接；远程无桌面服务器不能自动打开你电脑上的浏览器。 |
| API 请求失败 | 检查 Key、服务商余额和网络/代理；安装成功不代表账户已有可用模型额度。 |
| 旧书签返回 401/403 | 用当前启动链接重新配对，不要关闭认证或来源校验。 |
| 更新后没有新方案 | 检查这次任务是否成功；失败更新不会覆盖旧的已接受方案。 |
| 下载或 Open Path 报错 | 在已配对的浏览器中使用结果下载链接，不要复制服务器文件路径。 |

代理、后台常驻、内网访问和恢复方法见[运维指南](operations.md)。这是会执行问题代码的本地应用，向非可信用户开放前需要配置合适的隔离。
