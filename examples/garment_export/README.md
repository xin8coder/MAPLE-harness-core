# 中文外贸服装演示

## 场景

一家服装外贸公司要安排明天六批出口货物的验货、贴标、打包和进仓。
共有355箱、三个班组、两个仓区。需要决定订单顺序、班组和仓区，同时比较
总成本与逾期箱小时。不能拆单、超仓容或超过每日10小时的班组工时。
这是虚构业务数据，不是企业生产记录。

## 在 Harness 中操作

1. 新建对话，界面语言选中文。上传 `inputs/garment_export.xlsx`，发送
   `inputs/initial_request.txt`。选择进化求解，演示预算为种群60、迭代40。
2. 初次完成后，在结果卡片点击“查看并选择方案”。图上选点或表格选行，
   查看成本、逾期、订单安排、班组工时与仓区占用。保存的偏好不会自动变为下一轮约束。
3. 在同一对话发送 `inputs/update_1.txt`。它将英国衬衫订单截单时间提前两小时，
   并将乙组从四人改为三人。不要新建优化会话。
4. 更新后，在方案窗口顶部切换批次0与批次1，分别查看两轮方案，下载选中方案或全部CSV。

不用Excel时，将 `inputs/natural_language_data.txt` 和初始请求一起发送。
这份口述材料与工作簿内容一致。工作簿 `rules` 页说明时间基准、费用口径、容量和输出要求，
用户不用编写公式或Python。

## 已运行的演示

### 真实 Flash 版本（2026-09-29）

当前推荐会话为 `demo-garment-live-20260929-v2`。初始化与动态更新均由真实
`deepseek-v4-flash` 调用生成，使用应用的TSS编译和NSGA-II搜索流程。
两轮各使用种群60、40代、seed17，分别保留27和40个去重后的可行方案。
更新使用 `warm_restart_v1`，英国订单的截单改为开工后4.5小时，乙组人数由4改为3。

每个保留方案均通过独立公开规则核验，检查人工按人数计费、加班溢价、仓容、
最大班组工时、仓储与短驳费，以及逾期箱小时。费用误差不超过人民币0.000001元。
逾期核验仅允许完成时间保留六位小数所产生的量化误差，上界为总箱数乘0.0000005小时。
核验报告保存在会话的 `demo_validation_t000.json` 与 `demo_validation_t001.json` 中。
核验不改写模型代码、目标值或候选解。

第一次真实生成把每人时薪误当成整组时薪，该会话已标记核验失败，不作为有效演示。
之后在用户公开需求中明确了“甲组三人各工作一小时，人工费为66元”，再重新调用模型生成。
这项说明没有改变原Excel的计费规则。

### 保留的离线版本

2026-09-28 的真实 Flash 请求返回 `402 Insufficient Balance`，没有生成结果。
因此已部署的会话 `demo-garment-offline-20260928` **是离线数值演示**：
模型响应由 `offline_client.py` 明确给出的固定fixture替代，TSS编译、算子、NSGA-II搜索、
更新数据落盘、重启执行与导出经过实际应用服务运行。
它验证交互与数值流程，不代表LLM理解中文需求的成功率。

两轮各使用种群60、40代、seed17。去重后分别保留26和32个可行方案，均属于
各轮保留集中的非支配方案。目标相同但订单安排不同的方案可能在散点图中重叠，
仍可在表格中逐一选择。这不是26或32个不同的目标坐标，也不是全局最优性证明。

本例使用按实际作业计费的临时班组。班组人数减少会延长加工时间，同时减少整组换单
准备的计费人数，所以总成本不一定上升；计算规则在公开数据中保持一致。

## 复现

在集成目录，用应用虚拟环境的Python运行，`PYTHONPATH=src`：

```bash
python examples/garment_export/build_inputs.py
python examples/garment_export/run_demo.py --state-dir /tmp/garment-preflight
python examples/garment_export/run_demo.py --offline-demo --state-dir /tmp/garment-demo
```

运行真实API时，把 `--offline-demo` 改为 `--run-api`，并使用新的会话ID。
脚本只提交一次初始化和一次更新，每次最多两次代码修复，不覆盖现有会话。
真实运行会保存独立manifest，不复用离线fixture作为API结果。
初始化已经完成但更新尚未执行时，可使用 `--resume --session-id <已有会话>` 继续，
不会重复调用初始生成。
